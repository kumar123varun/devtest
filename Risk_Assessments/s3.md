## 2. About Amazon Simple Storage Service S3

### 2.1 Functional description

- Simple Storage Service (S3) is object-based storage that provides developers and IT teams with a secure, durable, highly scalable place to store data from anywhere.
- S3 is designed to be highly flexible. It supports storing any type and amount of data, reading the same data frequently or only for emergency disaster recovery, and building applications ranging from a simple FTP application to a sophisticated web application such as the Amazon.com retail website.
- Amazon S3 frees developers to focus on innovation instead of figuring out how to store their data.
- Amazon S3 offers storage classes based on the data access, resiliency, and cost requirements of workloads:
  - S3 Standard.
  - S3 Intelligent-Tiering.
  - S3 Standard-IA and S3 One Zone-IA.
  - S3 Glacier: Instant Retrieval, Flexible Retrieval, and Deep Archive.

### 2.2 Common use cases

- Log storage.
- Static website hosting.
- File storage and archiving.
- Media file storage.

## 5. Risk scenarios, recommendations, and detailed controls

### 5.1 XS0 — HIGH — Access from an untrusted network — R1 (Intrusion)

#### Scenario description

| Field | Source assessment |
| --- | --- |
| Scenario | An identity accesses the S3 service from an untrusted network. An SG network that is not explicitly allowed is considered untrusted. |
| Related risk | R1 (Intrusion) |
| Who? | An identity that initiates the operation, directly or indirectly, through a service identity, user credential, or service access key. The identity may belong to SG or “Microsoft/AWS Azure” (wording in source). |
| What? | Control and data plane. |
| Where? | From an untrusted network to the S3 service owned by SG. |
| How? | An identity connects to an S3 service using any client from an untrusted network and tries to access its control and data planes. The source uses the placeholder `$ServiceName` in this sentence. |

**Use cases**

- Public access is enabled on S3 through ACLs.
- Conditional access does not restrict access to the SG organization ID (`org_id`) in the S3 resource-based policy.

**Impact:** Access to service configuration and data from outside the Société Générale network may lead to data leakage, a data breach, and loss of intellectual property.

**Risk scope:** In Scope.

#### Feature risks and recommendations

The following recommendations and organizational restrictions are transcribed from `IMG_3065(2).jpeg`:

- Ensure S3 public access is not enabled. Block public access at account level. If that is not possible because of a business need, block public access at S3 access point and bucket levels using:
  - `BlockPublicAcls`.
  - `IgnorePublicAcls`.
  - `BlockPublicPolicy`.
  - `RestrictPublicBuckets`.
- Ensure only trusted user principals have access to S3 buckets through resource-based policies. Use only IAM and resource-based policies to grant bucket/object access. The source states that ACLs are no longer recommended by AWS.
- Use resource-based policies to ensure S3 is accessible only through VPC endpoints, using `aws:sourcevpce` (capitalization retained from source).
- The source states that limiting access to VPC endpoints secures presigned URLs.
- The source assigns `S3-XS0-A6-RestrictACLsCreation` a **Low** severity because the TnC forum still wants to track business units using “Enable ACLs” without a high/medium SLA.

**Organizational note in source:** Hosting a static website using Amazon S3 is not authorized. If required, a security exception must be requested. This is the assessment's organizational restriction; the general use-case list in Section 2.2 is retained separately.

The preventive and detective actions below are defined in the source to mitigate this risk.

- Ensure replication rules use a destination account that belongs to the SocGen organization.
- Ensure resource-based policies do not allow GetDataAccess with wildcard principals or resources.

### 5.3 XS2 — HIGH — Unencrypted Data REST — R5 (Regulatory)

#### Scenario description

| Field | Source assessment |
| --- | --- |
| Scenario | Data not protected by encryption at rest. |
| Related risk | R5 (Regulatory) |
| Who? | An identity that initiates the operation, directly or indirectly, through a service identity, user credential, or service access key. The identity may belong to SG or Microsoft/AWS. |
| What? | “Data stored in Plane.” (wording in source) |
| Where? | In the S3 service owned by SG. |
| How? / Use case | “Encryption is not enabled by default.” (statement in the source scenario) |
| Impact | Data may be read in clear by anyone with physical access to the disks or unauthorized IAM logical access through software. |

**S3 Glacier use case — source text:** Data at rest stored in S3 Glacier is automatically encrypted server-side using the 256-bit Advanced Encryption Standard (AES-256), with keys maintained by AWS. The source says that users who prefer to manage their own keys can also use client-side encryption before storing data in S3 Glacier.

**Risk scope:** In Scope.

#### Feature risks and recommendations

- Ensure all S3 buckets employ encryption at rest through default server-side encryption.
- The source lists these server-side encryption options:
  - Server-side encryption with Amazon S3-managed keys (SSE-S3).
  - Server-side encryption with a KMS key stored in AWS Key Management Service (SSE-KMS).
  - Server-side encryption with customer-provided keys (SSE-C).
- Block server-side encryption with customer-provided keys (SSE-C) and favor managed encryption options.

**Partially visible source update:** “Amazon S3 now applies server-side encryption with Amazon S3 managed keys (SSE-S3) as the base level of encryption for every …” `[Cropped]` — the sentence continues below the visible area of `IMG_3077.jpeg`.

**Source consistency note:** The scenario says encryption is not enabled by default, while the update on the same screenshot describes SSE-S3 as the base level of encryption. Both source statements are retained; this reconstruction does not resolve or independently validate them.

**Alternative measures to Skynet auto-remediate controls — source text:** Confidential data may be encrypted at the source (client side) with an appropriate cipher framework.
